# Bug Report: 同名不同扩展名的输入默认输出路径互相覆盖

**Type**: Untested flow
**Severity**: Low
**Feature**: 002-schema-csv-mask
**Reported**: 2026-09-11
**Status**: Patched
**Patched**: 2026-09-11

## Description

默认输出路径按"去扩展名的 stem"派生：`a.jsonl` 与 `a.csv` 的默认输出都是 `a.clean.jsonl` / `a.rejects.jsonl`——先后处理两个文件时后者静默覆盖前者的结果。

## Artifact Traceability

### spec.md / contracts (002)
- **Affected sections**: cli-contract.md 参数表默认值（`<输入名>.clean.<格式>`）
- **Gap identified**: 派生规则未考虑同 stem 不同扩展名的碰撞

### tasks.md (002)
- **Missing tasks**: 新增修复任务（见 T022）
- **受影响既有测试**: test_cli 中以 `input.csv` 期待 `input.clean.jsonl` 的用例需随规则更新

## Root Cause Analysis

v1 只有 JSONL 输入，stem 派生无碰撞；v2 引入 CSV 后未重新评估该规则。

## Recommended Fix

默认路径派生规则改为：仅剥离 `.jsonl` / `.json` 扩展名（保持 v1 行为不变）；其他扩展名（含 `.csv`）保留完整文件名作为基底——`a.csv` → `a.csv.clean.jsonl` / `a.csv.rejects.jsonl`，与 `a.jsonl` 的输出天然不冲突。显式 `-o/--rejects` 不受影响。
