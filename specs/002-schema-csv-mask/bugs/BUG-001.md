# Bug Report: 时间戳毫秒被静默丢弃并导致去重误杀

**Type**: Untested flow
**Severity**: High
**Feature**: 002-schema-csv-mask (缺陷根源在 001 引入的 cleaner)
**Reported**: 2026-09-11
**Status**: Patched
**Patched**: 2026-09-11

## Description

`10:00:00.123Z` 与 `10:00:00.456Z` 是两个不同时刻，`normalize_timestamp` 输出格式固定为 `%Y-%m-%dT%H:%M:%SZ`，二者清洗后都变成 `10:00:00Z`。配合 `--dedup-by id,timestamp`（去重发生在清洗之后）时，第二条被判为重复剔除——真实的数据丢失链路。

## Artifact Traceability

### spec.md (001)
- **Affected requirements**: FR-005（时间戳统一转换为 ISO 8601 UTC）
- **Gap identified**: 规范与澄清均未约定亚秒精度的处理；实现选择了秒级截断，未识别"截断 + 去重"的组合风险

### plan/research (001)
- **Affected sections**: research.md R2（`_OUTPUT_FORMAT = "%Y-%m-%dT%H:%M:%SZ"`）
- **Impact**: 输出格式需保留亚秒精度

### tasks.md (002)
- **Missing tasks**: 新增修复任务（见 T018）

## Root Cause Analysis

规范空白（亚秒精度未提及）→ 实现按最常见的秒级格式截断；R7 决定"清洗后去重"放大了截断的影响面。

## Recommended Fix

`normalize_timestamp` 保留亚秒精度：微秒非零时输出 `YYYY-MM-DDTHH:MM:SS.ffffffZ`（去除尾零）；微秒为零时维持秒级输出（与既有行为/断言兼容）。去重误杀随精度保留自然消除。
