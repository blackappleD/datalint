# Bug Report: 可选字段显式 null 被 type_error 硬拒

**Type**: Spec gap
**Severity**: Low
**Feature**: 002-schema-csv-mask (行为定义在 001 校验规则)
**Reported**: 2026-09-11
**Status**: Patched
**Patched**: 2026-09-11

## Description

`{"score": null}` 中 score 为可选字段（required: false），当前被 `type_error` 剔除。`required: false` 只被实现为"可缺失"，不等于 nullable——对 JSONL 来源（`null` 是一等公民）过于严格。

## Artifact Traceability

### spec.md (001)
- **Affected requirements**: FR-003 类型校验规则、data-model 校验规则表
- **Gap identified**: 规范未定义显式 `null` 的语义；实现将其落入类型不符分支

### tasks.md (002)
- **Missing tasks**: 新增修复任务（见 T023）

## Root Cause Analysis

规范只区分"存在/缺失"两态，未考虑 JSON 的第三态"显式 null"。

## Recommended Fix

可选字段值为 `null` → 视同缺失语义：跳过类型/枚举校验、跳过时间戳归一，`null` 原样保留在输出中（JSONL 输出 `null`，CSV 输出空单元格——后者已如此）。必填字段值为 `null` 仍为 `type_error`（null 不是合法的 string/number/timestamp/enum 值）。
