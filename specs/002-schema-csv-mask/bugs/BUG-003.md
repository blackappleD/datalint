# Bug Report: 去重字段缺失时所有缺失记录归入同一桶被静默剔除

**Type**: Spec conflict
**Severity**: Medium
**Feature**: 002-schema-csv-mask (行为定义在 001 FR-006)
**Reported**: 2026-09-11
**Status**: Patched
**Patched**: 2026-09-11

## Description

去重字段为可选字段（如 `score`）时，所有不含该字段的记录以 MISSING 哨兵作为相同键值互判重复——只保留第一条，其余全部静默剔除。缺失与空字符串 `""` 是分开的桶（这点正确），但"都缺失"不构成"内容相同"的合理证据。

## Artifact Traceability

### spec.md (001)
- **Affected requirements**: FR-006 与澄清记录"记录中可选字段缺失时按统一的'缺失值'参与去重比较"
- **Gap identified**: 001 澄清决策在真实数据上产生反直觉的批量数据丢失，用户判定为缺陷，决策被推翻

### tasks.md (002)
- **Missing tasks**: 新增修复任务（见 T020）
- **受影响既有测试**: `tests/test_cleaner.py::test_dedup_missing_optional_field_uses_sentinel` 断言旧行为，需随规范更新

## Root Cause Analysis

001 澄清阶段在"缺失值参与去重"与"缺失跳过去重"间选择了前者；实际数据中可选字段大面积缺失是常态，该选择导致隐性批量剔除。

## Recommended Fix

任一去重字段在记录中缺失 → 该记录跳过去重比较（始终保留，不产生 duplicate，也不注册键）。原 001 FR-006 相应语句以删除线保留历史。
