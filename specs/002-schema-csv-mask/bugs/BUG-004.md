# Bug Report: 无时区时间戳静默按 UTC 处理且无任何提示

**Type**: Untested flow
**Severity**: Medium
**Feature**: 002-schema-csv-mask (行为定义在 001 R2)
**Reported**: 2026-09-11
**Status**: Patched
**Patched**: 2026-09-11

## Description

`2026-09-11T10:00:00`（无时区信息）被直接视为 UTC 输出 `...10:00:00Z`。在 +08:00 的数据源上整批数据时刻偏移 8 小时，且用户得不到任何提示。

## Artifact Traceability

### spec.md (001/002)
- **Affected requirements**: 001 FR-005；002 澄清"无时区信息的输入视为 UTC"
- **Gap identified**: "视为 UTC"的假设本身保留（无更好的默认值），缺陷在于静默——用户无从得知发生了时区假定

### plan/research
- **Affected sections**: research 001 R2 / 002 R-204
- **Impact**: 清洗环节需统计"按 UTC 假定处理"的记录数并在运行结束时告警

### tasks.md (002)
- **Missing tasks**: 新增修复任务（见 T021）

## Root Cause Analysis

假设被正确实现但可观测性缺失——静默的隐式转换在下游才暴露为数据偏移。

## Recommended Fix

保留"无时区视为 UTC"行为；cleaner 统计 naive 时间戳数量，处理结束后 CLI 向 stderr 输出一次汇总警告（不影响退出码与报告统计）。
